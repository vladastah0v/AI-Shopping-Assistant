# Наполнение и управление каталогом

Генератор загружает синтетический каталог электроники и бытовой техники. Он создаёт 11 товарных категорий и два раздела верхнего уровня, 24 вымышленных бренда и четыре документа для каждой модели. Характеристики согласованы с назначением товара. Цены и остатки хранятся в товарной карточке, а документы содержат описание, технические параметры, рекомендации по первому использованию и ответы на частые вопросы.

## Наполнение каталога

Запустите Compose и примените миграции согласно [инструкции запуска](../README.md#локальный-запуск). Для стандартного набора выполните следующую команду.

```bash
docker compose run --rm migrate python -m scripts.seed_catalog --profile small --seed 42
```

| Профиль | Товары на один seed | Документы на один seed |
|---|---:|---:|
| `small` | 100 | 400 |
| `medium` | 1 000 | 4 000 |
| `large` | 10 000 | 40 000 |

По умолчанию используются `small` и seed `42`. Параметр `--seed` принимает целые числа от 0 до 18 446 744 073 709 551 615. Профиль `large` выбирается явно через `--profile large`.

- Один seed задаёт стабильные артикулы, UUID и свойства товаров. Например, первый артикул seed `42` — `SYN-2A-00001`. Временные метки проставляет PostgreSQL при фактической записи.
- Повторный запуск добавляет только отсутствующие записи. Изменённые цены, остатки и другие поля остаются в базе. Переход на больший профиль с тем же seed дополняет набор. Меньший профиль не удаляет ранее добавленные позиции.
- Другой seed добавляет отдельный набор товаров. Категории и бренды используются повторно по `slug` и имени. Если сгенерированный артикул уже принадлежит товару с другим UUID, транзакция откатывается.
- Команда сообщает число добавленных категорий, брендов, товаров и документов. Вставка выполняется пакетами в одной транзакции.

## Управление товарами

В локальном Compose команды запускаются через одноразовый сервис `migrate`. Этот сервис получает учётные данные `shopping_migrator`. Права записи определяет PostgreSQL. Роль HTTP API `shopping_app` имеет доступ к каталогу на чтение.

Просмотр возвращает JSON, подходящий для редактирования.

```bash
docker compose run --rm migrate python -m scripts.manage_catalog show SYN-2A-00001
```

Создание принимает JSON через stdin. Для примера используются категория и бренд, созданные генератором.

```bash
docker compose run --rm -T migrate python -m scripts.manage_catalog create STORE-NB-01 <<'JSON'
{
  "category_slug": "laptops",
  "brand_name": "Астролив",
  "name": "Астролив С100",
  "description": "Ноутбук для рабочих задач.",
  "price": "64990.00",
  "stock_quantity": 8,
  "specifications": {"ram_gb": 16, "ssd_gb": 512}
}
JSON
```

При обновлении передайте только изменяемые поля. Если указан `specifications`, переданный объект заменяет набор характеристик целиком.

```bash
docker compose run --rm -T migrate python -m scripts.manage_catalog update STORE-NB-01 <<'JSON'
{"price": "62990.00", "stock_quantity": 12}
JSON
```

Для снятия товара с публикации установите `is_active` в `false`. Команда `delete` удаляет товар и его документы. Повторное наполнение восстановит удалённый синтетический товар, если он входит в выбранный профиль и seed.

```bash
docker compose run --rm migrate python -m scripts.manage_catalog delete STORE-NB-01
```

Модульные проверки генератора запускаются через `uv run --locked pytest tests/unit/test_synthetic_catalog.py`. Интеграционные тесты наполнения и администрирования используют [изолированную тестовую базу](database.md#интеграционные-проверки).
