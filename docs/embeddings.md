# Генерация embeddings

Для русскоязычного каталога выбрана `intfloat/multilingual-e5-small` с лицензией MIT и размерностью 384. Это младшая модель семейства multilingual E5 для задач поиска. Авторы публикуют результаты на русскоязычной части Mr. TyDi. Оценка на товарных запросах проекта запланирована отдельно. [Карточка модели](https://huggingface.co/intfloat/multilingual-e5-small) · [Технический отчёт E5](https://arxiv.org/abs/2402.05672).

Провайдер использует Sentence Transformers на CPU, тип FP32 и закреплённую ревизию `614241f622f53c4eeff9890bdc4f31cfecc418b3`. Файл весов `model.safetensors` занимает около 470 МБ. При первом запуске дополнительно загружаются файлы токенизатора и конфигурации. [Файлы закреплённой модели](https://huggingface.co/intfloat/multilingual-e5-small/tree/614241f622f53c4eeff9890bdc4f31cfecc418b3).

На проверяемом Intel x86-64 доступны 16 ГиБ оперативной памяти, Docker выделено около 5,8 ГиБ и 2 CPU. Отдельный Linux-образ использует PyTorch CPU и два вычислительных потока. Размер собранного образа по `docker image inspect` — около 1,7 ГБ. Пиковое потребление памяти с весами E5 — `NOT_MEASURED`. При ограниченных ресурсах уменьшите `--batch-size` до `4` или `2`.

## Запуск

После [запуска сервисов](../README.md#локальный-запуск) и [наполнения каталога](catalog.md) соберите служебный образ.

```bash
docker compose build embeddings
```

Для первой загрузки весов запустите команду с явным разрешением сети.

```bash
docker compose run --rm embeddings python -m scripts.generate_embeddings --download-model
```

Кэш хранится в именованном томе `embedding_models`. Последующие запуски по умолчанию используют локальный кэш.

```bash
docker compose run --rm embeddings python -m scripts.generate_embeddings \
  --batch-size 8 --chunk-size 800 --chunk-overlap 120
```

Команда использует роль миграций для записи. Сеансовая блокировка PostgreSQL разрешает одну такую команду на базу, а изменения сохраняются пакетами. Перезапуск после сбоя пропускает уже обработанные данные с совпадающим хешем. Изменения записей после прохода их пакета учитываются при следующем запуске.

## Что кодируется

Для товара текст составляется из названия, артикула, категории, бренда, описания и характеристик. Цена и остаток остаются в каталоге как отдельные поля, поэтому их обновление не пересчитывает вектор. Документы делятся на фрагменты с перекрытием. Каждый фрагмент кодируется вместе с заголовком, а тип документа и источник хранятся в метаданных.

Сервис добавляет `query: ` к поисковым запросам и `passage: ` к товарам и документам. Провайдер применяет L2-нормализацию и ограничивает вход модели 512 токенами. Размер фрагмента и перекрытие задаются в символах, поэтому для особо длинных входов действует ограничение токенизатора. [Инструкция авторов модели](https://huggingface.co/intfloat/multilingual-e5-small#support-for-sentence-transformers).

## Повторные расчёты и версии

- SHA-256 рассчитывается для подготовленного текста. При совпадении `content_hash` используется сохранённый вектор. В пределах процесса повторяющиеся входы дополнительно используют ограниченный LRU-кэш.
- Смена текста или заголовка пересчитывает затронутые фрагменты. Смена ссылки обновляет метаданные без пересчёта вектора. Если в документе стало меньше фрагментов, команда удаляет лишние строки текущей версии.
- Версия кодирования включает ревизию весов, точность, нормализацию и лимит токенов. Смена модели или версии создаёт отдельный набор векторов. Схема принимает размерность 384, а модель с другой размерностью требует согласованной миграции.

## Проверка

Модульные проверки с тестовым провайдером запускаются через `uv run --locked pytest tests/unit/test_embeddings.py`. Для интеграционных проверок инкрементальной записи и косинусной метрики используйте [изолированную тестовую базу](database.md#интеграционные-проверки).
