# Эксплуатация

## Запуск и состояние

1. Скопируйте `.env.example` в `.env` и задайте разные пароли PostgreSQL для миграций и API.
2. Запустите `docker compose up -d --build --wait`.
3. Загрузите синтетический каталог командой `docker compose run --rm migrate python -m scripts.seed_catalog --profile small --seed 42`.
4. Проверьте Swagger, готовность и состояние модели.

```bash
curl -fsS http://127.0.0.1:8000/health/live
curl -fsS http://127.0.0.1:8000/health/ready
curl -fsS http://127.0.0.1:8000/health/ai
docker compose run --rm migrate alembic current
```

Для семантического поиска предварительно подготовьте веса и векторы. Для ответов языковой модели подключите локальную Ollama. Эти параметры можно включать независимо. [Embeddings](embeddings.md) · [Ollama](ollama.md) · [Мониторинг](observability.md).

## Сопровождение данных

Роль `shopping_migrator` применяет миграции и обновляет каталог. Роль `shopping_app` читает каталог, работает с сессиями и сохраняет оценки. Для обновления сервиса проверьте резервную копию и применяйте миграции вместе с версией приложения.

```bash
docker compose exec -T postgres pg_dump -U shopping_migrator -d shopping_assistant -Fc > shopping-assistant.dump
docker compose run --rm migrate alembic check
```

Храните резервную копию вне рабочего дерева и проверяйте восстановление в отдельной базе. Команда `docker compose down` останавливает сервисы с сохранением томов. PostgreSQL хранит историю диалогов до явного удаления или очистки. Истечение срока сессии закрывает доступ через Chat API. Временные снимки Redis истекают по TTL.

## Диагностика

| Наблюдение | Что проверить |
|---|---|
| `/health/ready` возвращает `503` | Поля `postgres` и `redis`, затем `docker compose logs --tail 100 api migrate postgres redis` |
| `/health/ai` возвращает `disabled` или `unavailable` | Включение провайдера, адрес Ollama и наличие выбранной модели |
| Семантический маршрут отвечает `503` | Веса, пространство векторов и конфигурацию `docker-compose.semantic.yml`. Гибридный маршрут указывает фактически применённую стратегию |
| Chat API возвращает `429` | Заголовок `Retry-After` и загрузку консультанта в метриках |
| Chat API возвращает `404` | Токен владельца, срок сессии и идентификатор ресурса |

При внешнем доступе ограничьте сетевой доступ к PostgreSQL, Redis, Ollama и метрикам. Принимайте HTTP через доверенный прокси с TLS и настройте доверенные адреса для передачи IP. [Границы действий и данных](security.md) · [Лимиты Redis](redis.md).

## Проверяемый диалог

Создайте сессию через `POST /api/v1/chat/sessions` с телом `{}`. Используйте возвращённый токен в Swagger или в заголовке `Authorization: Bearer …`.

1. «Подбери ноутбук до 80 000 рублей» задаёт категорию и бюджет.
2. «А если с 32 ГБ оперативной памяти?» сохраняет бюджет и добавляет требование к ОЗУ.
3. «Сравни первый и второй» использует порядок последней выдачи, когда есть две позиции. При недостатке позиций консультант запрашивает уточнение.
4. «SYN-2A-00001 есть в наличии?» проверяет остаток конкретного товара. Для артикула с нулевым остатком ответ указывает отсутствие на складе.
