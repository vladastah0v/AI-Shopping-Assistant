## 2026-11-27 — этап 1 из 22. Инициализация и инфраструктура

**Статус** — завершён.

Созданы базовый пакет FastAPI, конфигурация Pydantic Settings, асинхронные подключения к PostgreSQL и Redis, конфигурация Alembic и миграция `0001` для pgvector. Настроены Docker Compose, сборка образа, закрепление зависимостей в `uv.lock`, Ruff и pytest. Добавлены инструкции запуска и правила работы над проектом.

Миграции выполняются отдельным сервисом. API использует роль PostgreSQL `shopping_app` и запускается в контейнере с UID `10001`. Только HTTP-порт API опубликован на хосте и привязан к `127.0.0.1`. Проверки готовности выполняют векторный запрос и `PING` параллельно с ограничением времени.

- В Docker Desktop на macOS Intel запущены FastAPI, PostgreSQL 16.16, pgvector 0.8.7 и Redis 7.4.12. Подтверждены ревизия Alembic `0001`, доступность Swagger-схемы и ограничения роли PostgreSQL для API.
- При остановке PostgreSQL и Redis по очереди `/health/ready` возвращал HTTP 503, а `/health/live` — HTTP 200. После запуска зависимостей готовность восстанавливалась.
- В тестовой базе выполнены откат и повторное применение `0001`. Без расширения проверка готовности возвращала HTTP 503, после применения — HTTP 200.

### Исправленные проблемы

В конфигурацию pytest добавлен корень проекта для импорта `app` при запуске через CLI. Для тестов API использован асинхронный транспорт HTTPX с явным запуском жизненного цикла, что устранило предупреждение Starlette о прежнем тестовом клиенте. Сборка Compose использует один образ для API и миграций.

Проверки каталога, поиска и языковой модели относятся к последующим этапам. Проверка на другой архитектуре хоста — `NOT_RUN`.

## 2026-11-27 — этап 2 из 22. Модель данных каталога

**Статус** — завершён.

Добавлены ORM-модели категорий, брендов, товаров и товарных документов, общая метаинформация SQLAlchemy и миграция `0002`. Схема использует UUID, внешние ключи, точные цены `NUMERIC(14,2)`, временные метки с часовым поясом и индексы по связям и цене. Характеристики хранятся в JSONB с проверкой положительных числовых значений для ключей со стандартными единицами. Триггеры поддерживают `updated_at` у товаров и документов, а роль `shopping_app` получает права чтения каталога. [Схема базы и команды проверки](database.md).

### Выполненные проверки

- Обновление с `0001` до `0002`, откат до `0001` с сохранением pgvector и повторное применение `0002` прошли на PostgreSQL 16 в Docker Compose. `alembic current` показал `0002 (head)`, `alembic check` завершился успешно. Проверена генерация SQL в офлайн-режиме.
- Пройдено 23 теста, из них 8 модульных и 15 интеграционных. Падений и пропусков в полном запуске 0. Тесты проверили точную фильтрацию цен и характеристик, отказы на нарушениях ограничений, внешние ключи, права роли API, временные метки и удаление связанных документов.
- Покрытие строк `app` в процессе pytest — 99%. Покрытие процесса API внутри контейнера — `NOT_MEASURED`. Проверки Ruff, блокировки зависимостей и конфигурации Compose прошли.

### Исправленные проблемы

Проверка числовых ключей могла обратиться к JSONPath до проверки типа JSON. Добавлена проверка формы перед выполнением JSONPath, поэтому некорректные массивы теперь отклоняются ограничением `ck_products_specifications_object`.

Следующий этап добавит генератор синтетического каталога и административный способ работы с данными. При развёртывании вне Compose роль `shopping_app` создаётся до применения `0002`.

Рекомендуемое название коммита — `feat: добавить модели и миграцию каталога`.

## 2026-11-27 — этап 4 из 22. Публичный API каталога

**Статус** — завершён.

Подключены шесть маршрутов FastAPI для чтения категорий, брендов, товаров, характеристик и сравнения. Фильтры по категории, бренду, цене, наличию и техническим параметрам применяются в PostgreSQL. Фильтр категории включает подкатегории. Для операций с ценой используется одна валюта, по умолчанию `RUB`. Пагинация запрашивает на одну запись больше размера страницы для определения `has_more`. Сортировка использует UUID как дополнительный критерий. Сравнение сохраняет порядок входных UUID и возвращает `null` для отсутствующего значения. [Документация API](api.md).

### Выполненные проверки

- В Docker Compose проверены все шесть маршрутов, Swagger, совместная фильтрация и порядок сравнения на стандартном каталоге из 100 товаров. Публичная попытка записи получила `405`.
- При проверке числовых характеристик учтены существующие записи с нечисловыми значениями в дополнительных JSONB-полях. Такие записи исключаются из числовой выдачи, остальные товары продолжают возвращаться.
- Принудительная блокировка таблицы и остановка PostgreSQL вызывали HTTP `503`. После снятия блокировки и запуска базы каталог снова отвечал HTTP `200`.
- Пройдено 49 тестов, из них 15 модульных и 34 интеграционных. Падений и пропусков в полном запуске 0. Покрытие строк `app` в процессе pytest — 96%. Покрытие процесса API внутри контейнера — `NOT_MEASURED`.
- `ruff check`, `ruff format --check`, `uv lock --check`, `alembic check` и сборка Docker Compose прошли. Нагрузочное тестирование — `NOT_RUN`.

Следующий этап добавит генерацию embeddings для товаров и фрагментов документов.
