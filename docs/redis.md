# Redis и ограничения трафика

Поиск и векторы запросов используют отдельные кэши. Ключи содержат хеш параметров, версию стратегии и пространство embeddings. Для выдачи дополнительно учитывается ревизия каталога. Триггеры PostgreSQL обновляют ревизию в транзакции записи при изменении товаров, брендов, категорий, документов и векторов. Гибридный ответ, полученный в резервном текстовом режиме, не сохраняется под ключом гибридной стратегии.

Кэш помещает краткоживущую блокировку на вычисление. Остальные клиенты некоторое время ждут готовое значение. Если оно не появится или Redis недоступен, поиск выполнится без кэша. Ответы Chat API с персональным контекстом не попадают в общий кэш. [Состояние диалога](conversations.md).

| Параметр | Значение по умолчанию |
|---|---:|
| `SHOPPING_CACHE_ENABLED` | `true` |
| `SHOPPING_SEARCH_CACHE_TTL_SECONDS` | 60 |
| `SHOPPING_EMBEDDING_CACHE_TTL_SECONDS` | 900 |
| `SHOPPING_API_REQUESTS_PER_MINUTE` | 120 |
| `SHOPPING_ACTIVE_AI_REQUESTS` | 4 |

Лимиты считаются по IP отдельно для поиска и чата. Чат также ограничивает число одновременных сообщений и потоков во всех процессах API. Аренда слота восстанавливается по таймауту при аварийном завершении процесса. При превышении лимита возвращается `429` и `Retry-After`. При недоступности Redis обычный поиск работает напрямую, а Chat API возвращает `503`. Разрешайте прокси передавать IP клиента только с доверенных адресов. [Счётчик Redis](https://redis.io/docs/latest/commands/incr/).
