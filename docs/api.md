# Публичный API каталога

Маршруты доступны с префиксом `/api/v1`. Интерактивная документация находится в `/docs`, схема OpenAPI — в `/openapi.json`.

| Метод и путь | Результат |
|---|---|
| `GET /api/v1/categories` | Категории с кодами `slug` и идентификаторами родителей |
| `GET /api/v1/brands` | Бренды с описаниями и UUID |
| `GET /api/v1/products` | Активные товары с краткими сведениями, ценой, валютой и складским остатком |
| `GET /api/v1/products/{id}` | Карточка активного товара с описанием и характеристиками |
| `GET /api/v1/products/{id}/specifications` | UUID активного товара и его технические характеристики |
| `POST /api/v1/products/compare` | Сопоставление характеристик выбранных товаров |

## Пагинация и сортировка

Все списки возвращают `items`, `limit`, `offset` и `has_more`. Значения по умолчанию — `limit=20` и `offset=0`. Допустимый размер страницы — от 1 до 100. Для следующей страницы увеличьте `offset` на `limit`, если `has_more` равно `true`.

Категории и бренды сортируются по названию. Для товаров доступны `name_asc`, `name_desc`, `price_asc`, `price_desc`, `rating_desc`, `newest` и `stock_desc`. Сортировка по умолчанию — `name_asc`. При равенстве значений порядок определяется UUID. При сортировке по рейтингу товары без рейтинга располагаются в конце.

## Фильтрация товаров

Условия одного запроса применяются одновременно.

| Параметр | Условие |
|---|---|
| `category_id` или `category_slug` | Выбранная категория и её подкатегории. При двух параметрах и разных категориях список пуст. |
| `brand_id` | UUID бренда из списка брендов |
| `min_price`, `max_price` | Границы цены включительно, с точностью до двух знаков после запятой |
| `currency` | Трёхбуквенный код валюты. Для фильтрации или сортировки по цене при отсутствии параметра используется `RUB`. |
| `in_stock` | `true` для товаров с положительным остатком, `false` для товаров с нулевым остатком |
| `spec` | Условие в формате `ключ:оператор:значение`. Можно передать до 12 условий. |

Для числовых полей поддерживаются `eq` (равно), `gte` (не меньше) и `lte` (не больше). Используйте обычную десятичную запись с точкой. Допустимы [числовые ключи схемы](database.md#технические-характеристики), а также `depth_mm`, `freezer_volume_l` и `spin_speed_rpm`. Товар с отсутствующим или нечисловым значением исключается из результата числового фильтра.

Для `cpu`, `gpu`, `os`, `panel`, `connection`, `form_factor`, `noise_cancellation`, `component_type`, `interface`, `defrost_type` и `appliance_type` поддерживается точное сравнение `eq` с учётом регистра.

```bash
curl -fsSG 'http://127.0.0.1:8000/api/v1/products' \
  --data-urlencode 'category_slug=laptops' \
  --data-urlencode 'spec=ram_gb:gte:16' \
  --data-urlencode 'spec=os:eq:Linux' \
  --data-urlencode 'max_price=80000' \
  --data-urlencode 'in_stock=true'
```

Цены и рейтинги сериализуются в десятичные строки. Рейтинг без значения возвращается как `null`.

## Сравнение товаров

Передайте от двух до пяти разных UUID в поле `product_ids`. UUID можно взять из `items` ответа `GET /api/v1/products`. Операция сравнения читает каталог и сохраняет порядок входного списка.

```bash
first_product_id='UUID первого товара'
second_product_id='UUID второго товара'
curl -fsS 'http://127.0.0.1:8000/api/v1/products/compare' \
  -H 'Content-Type: application/json' \
  --data "{\"product_ids\":[\"$first_product_id\",\"$second_product_id\"]}"
```

В `products` находятся краткие карточки, а в `specifications` — значения по каждому ключу в том же порядке. Если у одного товара характеристика отсутствует, для него возвращается `null`. Валюта каждой цены указана в соответствующей карточке.

## Ошибки

- `404` — карточка недоступна в публичном каталоге. Сравнение возвращает `404`, если хотя бы один товар отсутствует или снят с публикации.
- `422` — параметры или тело запроса не прошли валидацию.
- `503` — PostgreSQL временно недоступен или чтение превысило `SHOPPING_DEPENDENCY_TIMEOUT_SECONDS`. Значение по умолчанию — 2 секунды.
