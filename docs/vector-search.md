# Векторный поиск

Поиск сравнивает вектор запроса с векторами товаров или фрагментов через косинусное расстояние pgvector. Меньшее расстояние означает более близкий результат. Каждый запрос ограничен конкретной парой `embedding_model` и `embedding_version`.

## Режимы

| Режим | Выполнение |
|---|---|
| `exact` | Вычисляет расстояние для всех подходящих строк и берёт первые `top_k`. При равном расстоянии порядок задаёт UUID. |
| `hnsw` | Использует запрос, пригодный для HNSW. План выбирает PostgreSQL. Включено итеративное сканирование `strict_order`. Если запрос вернул меньше `top_k` результатов, выполняется точный поиск с теми же условиями. |

Миграция `0004` создаёт частичные HNSW-индексы с `vector_cosine_ops` и параметрами `m=16` и `ef_construction=64`. Изначально в них входит закреплённая версия E5. Пара модели и версии присутствует в SQL в виде экранированных литералов, чтобы планировщик мог сопоставить условия запроса с предикатом индекса. Остальные параметры передаются как параметры SQL. Векторные пространства без своего HNSW-индекса доступны через точный план PostgreSQL. [Частичные индексы PostgreSQL](https://www.postgresql.org/docs/16/indexes-partial.html) · [Режимы pgvector](https://github.com/pgvector/pgvector#hnsw).

Оба режима применяют условия каталога в базе. Фильтры включают категорию с подкатегориями, бренд, бюджет, валюту, наличие и характеристики. Учитываются только опубликованные товары. Для фрагментов действуют условия связанного товара и, при необходимости, тип документа. Фрагмент возвращается с идентификаторами товара и документа, заголовком и ссылкой на источник. [Синтаксис характеристик](api.md#фильтрация-товаров).

## Использование в приложении

`VectorSearch` использует действующую асинхронную сессию PostgreSQL и провайдер embeddings. `VectorSearchOptions` задаёт `top_k` от 1 до 100 и `ef_search` от 1 до 1000. По умолчанию используются `hnsw`, `top_k=10` и `ef_search=100`. Параметры HNSW применяются только в текущей транзакции.

```python
from app.ai.embeddings.huggingface import SentenceTransformersProvider
from app.ai.embeddings.service import EmbeddingService
from app.ai.retrieval.vector import VectorSearch, VectorSearchOptions
from app.modules.catalog.schemas import ProductFilters

search = VectorSearch(EmbeddingService(SentenceTransformersProvider()))
filters = ProductFilters(
    category_slug="laptops", max_price=80000, in_stock=True, spec=["ram_gb:gte:16"]
)
options = VectorSearchOptions(top_k=5, mode="hnsw")
products = await search.find_products(
    session, "Ноутбук для программирования", filters=filters, options=options
)
documents = await search.find_documents(
    session, "Ноутбук для программирования", filters=filters, options=options
)
```

Для готовых векторов доступны `search_product_vectors` и `search_document_vectors`. Перед вызовом текстового поиска подготовьте [локальную модель и сохранённые векторы](embeddings.md).

## Переиндексация

Для закреплённой версии E5, после генерации векторов, выполните команду из корня проекта.

```bash
docker compose run --rm migrate python -m scripts.rebuild_index
```

Для другой модели или версии сначала запишите её векторы, затем явно укажите оба значения.

```bash
docker compose run --rm migrate python -m scripts.rebuild_index \
  --model 'идентификатор модели' --version 'версия векторов'
```

Команда проверяет наличие векторов, исключает параллельную генерацию и перестраивает пару индексов в одной транзакции. Сначала строятся обе замены, затем они занимают имена прежних индексов. При ошибке PostgreSQL сохраняет прежнюю пару. Векторы всех версий остаются в таблицах. Во время обычного построения индекса PostgreSQL блокирует запись в индексируемые таблицы. При финальной замене требуется блокировка и для чтения. Лимит ожидания блокировки — 5 секунд. [Блокировки при построении индекса](https://www.postgresql.org/docs/16/sql-createindex.html).

Аргументы команды выбирают пространство для HNSW. Пространство конкретного текстового запроса задаёт провайдер, переданный в `VectorSearch`.

## Проверка

Интеграционные тесты выполняют запросы обоих типов на PostgreSQL, проверяют изоляцию версий, обязательные фильтры и откат замены индексов. `EXPLAIN` проверяет наличие HNSW в плане при настройках, предпочитающих индексный доступ. Сравнение задержек и Recall@K запланировано на этап нагрузочных испытаний. [Запуск интеграционных тестов](database.md#интеграционные-проверки).
