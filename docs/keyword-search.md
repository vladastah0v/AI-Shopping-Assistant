# Полнотекстовый поиск

Поиск работает по товарам и товарным документам в PostgreSQL. Конфигурация `pg_catalog.russian` обрабатывает русские словоформы. При индексировании и поиске `ё` приравнивается к `е`, а распространённые типографские дефисы и тире приводятся к обычному дефису. `plainto_tsquery` требует совпадения всех значимых лексем после удаления стоп-слов. Встроенный словарь может давать разные лексемы для форм одного слова, как в случае «память» и «памятью». [Разбор поисковых запросов PostgreSQL](https://www.postgresql.org/docs/16/textsearch-controls.html).

## Индексы и ранжирование

- В товаре индексируются название, артикул, текст JSONB-характеристик и описание. Наибольший вес получают название и артикул, затем характеристики и описание. В документе заголовок весит больше основного текста.
- Точное совпадение артикула без учёта регистра получает оценку `2`. Совпадение после приведения регистра и удаления небуквенно-цифровых символов получает `1`. Остальные совпадения ранжируются по `ts_rank_cd` с нормализацией. При равной оценке порядок определяется UUID.
- PostgreSQL хранит вычисляемое поле `tsvector` и строит по нему GIN. По нормализованным артикулам используется B-tree. Миграция `0005` заполняет поля существующих строк, а PostgreSQL обновляет их при вставке и изменении данных. [Вычисляемые полнотекстовые поля](https://www.postgresql.org/docs/16/textsearch-tables.html).
- Для предсказуемого размера поисковых полей индексируются первые 16 000 символов описания товара, 8 192 символа текстового представления характеристик и 65 536 символов документа. Исходные данные хранятся целиком. [Ограничения полнотекстового поиска PostgreSQL](https://www.postgresql.org/docs/16/textsearch-limitations.html).

## Использование

`search_products_by_keywords` и `search_documents_by_keywords` принимают асинхронную сессию SQLAlchemy. `top_k` лежит в диапазоне от 1 до 100, по умолчанию `10`. Запрос может содержать до 512 символов. Пустой запрос отклоняется. Если текст состоит из пунктуации или стоп-слов и нормализованный артикул не совпал, возвращается пустая выдача.

Оба метода применяют условия каталога по категории, бренду, бюджету, наличию и характеристикам. Поиск документов также принимает тип документа и возвращает UUID товара и документа, заголовок и источник. [Параметры фильтрации](api.md#фильтрация-товаров).

```python
from app.ai.retrieval.keyword import search_documents_by_keywords, search_products_by_keywords
from app.modules.catalog.schemas import ProductFilters

filters = ProductFilters(
    category_slug="laptops", max_price=80000, in_stock=True, spec=["ram_gb:gte:16"]
)
products = await search_products_by_keywords(session, "программирование", filters=filters)
documents = await search_documents_by_keywords(session, "оперативная память", filters=filters)
```

## Проверка

Модульные тесты валидации запускаются через `uv run --locked pytest tests/unit/test_keyword_search_arguments.py`. Интеграционные проверки словоформ, приоритета артикулов, фильтров, обновления индекса и планов `EXPLAIN` используют [тестовую базу PostgreSQL](database.md#интеграционные-проверки).
