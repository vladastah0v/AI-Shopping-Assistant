# Работа над AI Shopping Assistant

## Этапы

- План состоит из 22 этапов. Перед возобновлением работы прочитай `docs/implementation-status.md` и `docs/development-log.md`, затем проверь состояние рабочей папки.
- Начинай только этап, который пользователь явно поручил. Укажи номер и название, кратко опиши цели и перечисли задачи этапа.
- Перед завершением проверь изменения, запусти доступные тесты, `ruff check` и `ruff format --check`, исправь найденные проблемы и обнови документацию и журнал разработки.
- После отчёта остановись. Переход к следующему этапу происходит по явной команде пользователя. При критической проблеме укажи статус и опиши, что остаётся проверить или исправить.

## Git и GitHub

- Пользователь управляет индексом Git, коммитами, ветками, тегами, рабочим деревом через Git, настройками удалённых репозиториев и публикацией.
- Команды агента ограничены операциями для чтения. Используй `git status`, `git diff`, `git log`, `git branch` для просмотра, `git remote -v` и `git rev-parse`.
- После каждого этапа предложи название коммита в формате Conventional Commits. Используй стандартный тип (`feat`, `fix`, `chore`, `docs` и другие) и описание изменений на русском языке.

## Язык и данные

- README, документация, отчёты, подписи диаграмм, описания Swagger и сообщения консультанта пишутся на русском языке.
- Идентификаторы в коде и базе, имена файлов, метрики, технические комментарии и docstrings пишутся на английском языке.
- Для разработки и тестирования используй синтетические товары и документы. Профиль `small` применяется по умолчанию. Запускай профиль `large` и тяжёлые бенчмарки, устанавливай Ollama и загружай большие модели только по явной команде пользователя. Для выбора модели заранее укажи размер загрузки и требования к ресурсам. До ресурсоёмких операций проверь ограничения среды.

## Отчёт по этапу

Заголовок имеет формат «Этап N из 22 — название». Укажи статус, реализованное, созданные и изменённые файлы, архитектурные решения, тесты, Ruff, интеграционные проверки и покрытие, если оно измерялось. Добавь обнаруженные и исправленные проблемы, оставшиеся ограничения, команды проверки, рекомендуемое название коммита и следующий этап. Для непроведённых проверок используй `NOT_RUN`, для метрик без замера — `NOT_MEASURED`. Отдельно обозначай проверки с тестовыми провайдерами. Заверши отчёт статусом Git и указанием, что переход к следующему этапу ждёт команды пользователя.
