# AI Shopping Assistant

AI Shopping Assistant — серверное приложение для подбора и сравнения товаров интернет-магазина электроники и бытовой техники. Сервис предназначен для подбора товаров по бюджету и характеристикам, объяснения рекомендаций и обработки уточнений в диалоге. Источником цен, остатков и характеристик служит каталог. Для разработки и тестирования предусмотрены синтетические данные.

Основные компоненты — FastAPI, PostgreSQL 16 с pgvector, Redis, LangChain и локальная Ollama. API поддерживает поиск по тексту и векторам, контекстные рекомендации, проверку источников и ответы через SSE. [Архитектура](docs/architecture.md) · [Схема базы](docs/database.md) · [Эксплуатация](docs/operations.md).

## Локальный запуск

Понадобятся Docker и Docker Compose. Для локального запуска проверок на хосте также нужны Python 3.12 и uv.

```bash
cp .env.example .env
```

В `.env` укажите разные локальные пароли для `POSTGRES_PASSWORD` и `SHOPPING_POSTGRES_PASSWORD`, затем запустите сервисы.

```bash
docker compose up --build --wait
```

Swagger доступен по адресу [127.0.0.1:8000/docs](http://127.0.0.1:8000/docs). Если порт занят, укажите свободный `API_PORT` в `.env` и используйте его в URL.

| Компонент | Назначение |
|---|---|
| `api` | Запускает FastAPI от непривилегированного пользователя. Порт по умолчанию доступен только через `127.0.0.1`. |
| `postgres` | Хранит данные приложения. При первом запуске создаёт роль `shopping_app` для API. |
| `redis` | Предоставляет хранилище для временных данных во внутренней сети Compose. |
| `migrate` | Применяет миграции Alembic с отдельными учётными данными. API запускается после успешной миграции. |

Чтобы отдельно применить миграции в уже инициализированном окружении, выполните `docker compose run --rm migrate`. Пароли в `.env` используются при начальной настройке базы. Для ротации на существующем томе сначала обновите пароли ролей в PostgreSQL, затем приведите `.env` в соответствие с ними.

## Наполнение каталога

После запуска сервисов загрузите начальный набор и проверьте карточку по артикулу.

```bash
docker compose run --rm migrate python -m scripts.seed_catalog
docker compose run --rm migrate python -m scripts.manage_catalog show SYN-2A-00001
```

По умолчанию команда создаёт 100 товаров с seed `42`. Список профилей, правила повторного запуска и примеры редактирования описаны в [инструкции по работе с каталогом](docs/catalog.md).

## API каталога

Пример подбора ноутбуков в наличии с 16 ГБ оперативной памяти или больше и ценой до 80 000 рублей.

```bash
curl -fsSG 'http://127.0.0.1:8000/api/v1/products' \
  --data-urlencode 'category_slug=laptops' \
  --data-urlencode 'max_price=80000' \
  --data-urlencode 'in_stock=true' \
  --data-urlencode 'spec=ram_gb:gte:16' \
  --data-urlencode 'sort=price_asc'
```

Все публичные маршруты, параметры и примеры сравнения описаны в [документации API](docs/api.md).

[Chat API](docs/chat-api.md) предоставляет анонимные сессии, контекстные рекомендации, SSE и обратную связь. [Подключение Ollama](docs/ollama.md).

## Генерация embeddings

Товары и документы преобразуются в векторы отдельной пакетной командой. Для неё предусмотрен CPU-образ `embeddings`. Модель и параметры загрузки описаны в [инструкции генерации](docs/embeddings.md).

Модуль поиска поддерживает точный режим и HNSW для товаров и фрагментов документов. Оба режима учитывают условия каталога. [Параметры поиска и переиндексация](docs/vector-search.md).

Полнотекстовый поиск PostgreSQL учитывает русские словоформы, артикулы, модели и технические термины. Три HTTP-маршрута предоставляют полнотекстовый, семантический и гибридный поиск с обязательными фильтрами. [Search API](docs/search-api.md) · [Полнотекстовое ранжирование](docs/keyword-search.md).

## Проверки состояния

```bash
curl --fail http://127.0.0.1:8000/health/live
curl --fail http://127.0.0.1:8000/health/ready
```

`GET /health/live` проверяет, что процесс API отвечает. `GET /health/ready` выполняет векторный запрос в PostgreSQL и `PING` в Redis. При отказе любой зависимости API возвращает HTTP 503 и отдельно указывает состояние PostgreSQL и Redis. Таймаут проверки каждой зависимости настраивается через `SHOPPING_DEPENDENCY_TIMEOUT_SECONDS`.
