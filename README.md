# AI Shopping Assistant

AI Shopping Assistant — серверное приложение для подбора и сравнения товаров интернет-магазина электроники и бытовой техники. Сервис предназначен для подбора товаров по бюджету и характеристикам, объяснения рекомендаций и обработки уточнений в диалоге. Источником цен, остатков и характеристик служит каталог. Для разработки и тестирования предусмотрены синтетические данные.

На текущем этапе доступна инфраструктура API с PostgreSQL 16, pgvector и Redis. Актуальный объём реализации описан в [плане разработки](docs/implementation-status.md) и [журнале изменений](docs/development-log.md).

## Локальный запуск

Понадобятся Docker и Docker Compose. Для локального запуска проверок на хосте также нужны Python 3.12 и uv.

```bash
cp .env.example .env
```

В `.env` укажите разные локальные пароли для `POSTGRES_PASSWORD` и `SHOPPING_POSTGRES_PASSWORD`, затем запустите сервисы.

```bash
docker compose up --build --wait
```

Swagger доступен по адресу [127.0.0.1:8000/docs](http://127.0.0.1:8000/docs). Если порт занят, укажите свободный `API_PORT` в `.env` и используйте его в URL.

| Компонент | Назначение |
|---|---|
| `api` | Запускает FastAPI от непривилегированного пользователя. Порт по умолчанию доступен только через `127.0.0.1`. |
| `postgres` | Хранит данные приложения. При первом запуске создаёт роль `shopping_app` для API. |
| `redis` | Предоставляет хранилище для временных данных во внутренней сети Compose. |
| `migrate` | Применяет миграции Alembic с отдельными учётными данными. API запускается после успешной миграции. |

Чтобы отдельно применить миграции в уже инициализированном окружении, выполните `docker compose run --rm migrate`. Пароли в `.env` используются при начальной настройке базы. Для ротации на существующем томе сначала обновите пароли ролей в PostgreSQL, затем приведите `.env` в соответствие с ними.

## Проверки состояния

```bash
curl --fail http://127.0.0.1:8000/health/live
curl --fail http://127.0.0.1:8000/health/ready
```

`GET /health/live` проверяет, что процесс API отвечает. `GET /health/ready` выполняет векторный запрос в PostgreSQL и `PING` в Redis. При отказе любой зависимости API возвращает HTTP 503 и отдельно указывает состояние PostgreSQL и Redis. Таймаут проверки каждой зависимости настраивается через `SHOPPING_DEPENDENCY_TIMEOUT_SECONDS`.

## Тесты и качество кода

```bash
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest tests/unit
```

Для интеграционной проверки укажите адрес работающего API. Команда запускает весь набор тестов и выводит покрытие кода, исполненного в процессе pytest.

```bash
SHOPPING_TEST_BASE_URL=http://127.0.0.1:8000 \
  uv run --locked pytest --cov=app --cov-report=term-missing
```

`docker compose down` останавливает сервисы и сохраняет данные в именованных томах.
